# Capstone: Distributed Edge Computing and Telemetry Platform (DECTP)

One increasingly sophisticated system, built across the curriculum with simulated, non-sensitive data. Individual projects stay in separate directories and feed the capstone through documented interfaces.

## Evolution

| Month | What I build | What it teaches |
|---|---|---|
| 3 | Python telemetry analyzer | Programming and software construction |
| 6 | C/C++ processing library | Memory, algorithms, compiled software |
| 9 | Linux monitoring service | Operating systems and concurrency |
| 12 | Distributed telemetry backend | Networking and distributed systems |
| 15 | Full-stack management application | Software architecture and application development |
| 18 | AWS cloud deployment | Cloud and DevOps |
| 21 | STM32 telemetry node | Embedded and real-time software |
| 24 | Rust component, GPU/FPGA exploration, assurance package | Heterogeneous computing and verification |
| 27 | Hardware security analysis | Side channels, secure boot, hardware trust |
| 30 | Principal-level technical package | Architecture, security assessment, V&V |

## Target architecture

| Layer | Technology |
|---|---|
| Physical sensors | Simulated and physical sensors |
| Embedded acquisition | STM32, ARM Cortex-M, C, FreeRTOS |
| Edge gateway | NXP i.MX, Linux, C++ / Rust |
| GPU processing | NVIDIA CUDA |
| FPGA processing | AMD/Xilinx |
| Cloud infrastructure | AWS, Docker, Terraform, distributed services |
| Application and data | Python, PostgreSQL, React, TypeScript |
| Operator interface | Telemetry, visualization, configuration, alerts |

## Final deliverable (Months 28-30)

- Software requirements
- Verification and validation plan
- Deployment architecture
- Performance analysis
- Reliability and resilience analysis
- Software bill of materials
